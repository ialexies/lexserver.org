## Commands

```bash
npm run dev        # Start Vite dev server (http://localhost:5173)
npm run build      # Production build -> dist/
npm run preview    # Serve the production build locally
npm run lint       # ESLint (TypeScript + React hooks + Prettier)
npm run format     # Prettier write
npm run test:e2e   # Build, then Playwright (mobile 375, tablet 768, desktop 1440)
npx tsc --noEmit   # Typecheck (CI runs this)
```

First time running the e2e tests on a machine: `npx playwright install`.

Docker (host port 8085 -> nginx 80):

```bash
docker compose up --build
```

## Architecture

A client-rendered React SPA (Vite + TanStack Router file routes, no SSR) for the Builds Worlds
Studio site. Routes live in `src/routes/`: `/`, `/work`, `/about`, `/blog`, `/blog/$slug`, and
`/lupaatbahay` (a product case study). `src/routeTree.gen.ts` is generated by the router plugin.

Static pages in `public/` are served as-is, and win over SPA routes of the same path:
`public/indexwise/` (the Indexwise landing page) and `public/indexwise/privacy/` (its privacy
policy, which the Chrome Web Store listing links to — keep that URL stable). Do not add a React
route at `/indexwise`; it would be shadowed.

### Data flow

Page content lives in [src/lib/portfolio-data.ts](src/lib/portfolio-data.ts) as typed exported
constants (`PROFILE`, `METRICS`, `SERVICES`, `PROCESS`, `PORTFOLIO`, `PRODUCTS`, `TECH`,
`TESTIMONIALS`, `PRICING`, `TEAM`, experience and awards). Section components read from it, so
most copy changes are edits to that one file. A few strings are hardcoded in components or route
files (the hero, the `/work` and `/about` intros, `/lupaatbahay` page copy). Blog posts are
markdown in `src/blog/posts/` (`YYYY-MM-DD-slug.md`), loaded by `src/lib/blog.ts`.

Adding a product: add an `OwnProduct` to `PRODUCTS`. An internal `url` starting with `/` renders as
"Learn more"; `storeLinks.website` and `storeLinks.chrome` render extra buttons.

### Components

Page sections are in [src/components/portfolio/](src/components/portfolio/). `Reveal.tsx` is the
framer-motion scroll-reveal wrapper (respects `prefers-reduced-motion`), `SectionHeading.tsx` is the
shared heading, `Nav.tsx` is the sticky nav, and `OfficeDemo.tsx` embeds the AI Office preview in an
iframe. `src/components/ui/` is stock shadcn and mostly unused.

### Styling

Tailwind CSS v4 with light and dark themes (toggle in the nav; the `dark` class on `<html>` is set
by an inline script in `index.html`). Tokens in [src/styles.css](src/styles.css): `bg-paper`,
`text-ink`, `bg-pop` (orange `#ff5722`), `bg-canvas`, `bg-surface`. Fonts: Archivo Black
(`font-display`), Hind (body), JetBrains Mono. Shadows are soft (`.shadow-brut*`), radii are small.

### Images

Product and case-study images are webp in `public/products/`. Keep them under ~150 KB each. Nginx
CSP `img-src` only allows `'self'`, `data:` and picsum.photos, so externally hosted images are
blocked until the CSP is updated.

## Build and deployment

Vite builds a static bundle into `dist/`. The Docker image is two-stage: Node 22 builds, then
nginx:alpine serves `dist/` with `try_files $uri $uri/ /index.html` and the security headers and CSP
from [nginx.conf](nginx.conf). The CSP must list every external origin the site uses: currently
Google Fonts, picsum.photos, and `frame-src https://aiteampreview.lexserver.org` for the AI Office
demo (it is repeated in each `location` block).

### CI/CD

[.github/workflows/ci.yml](.github/workflows/ci.yml):

- `verify` (GitHub-hosted, every push and pull request): `npm ci --legacy-peer-deps`, lint,
  `tsc --noEmit`, build.
- `deploy` (self-hosted runner on lexserver, label `lexserver`, push to `main` only, after
  `verify`): tags the current image `lexserver-web-web:previous`, runs
  `docker compose -p lexserver-web up -d --build`, health-checks `/`, `/lupaatbahay` and
  `/indexwise/` on port 8085, and rolls back to `:previous` if any fail.

The compose project name `lexserver-web` must stay: it produces the container
`lexserver-web-web-1`, the image `lexserver-web-web`, and the network `lexserver-web_default`.

One-time runner setup on the server (runners are per repo; the existing lupaatbahay one cannot
serve this repo). Get a registration token from GitHub (repo -> Settings -> Actions -> Runners ->
New self-hosted runner), then:

```bash
ssh ialexies@192.168.0.253
mkdir -p ~/actions-runner-lexserver-org && cd ~/actions-runner-lexserver-org
# download and extract the runner release (same version as ~/actions-runner-homescout)
./config.sh --url https://github.com/ialexies/lexserver.org --token <TOKEN> \
  --name lexserver-org --labels self-hosted,lexserver --unattended --work _work
sudo ./svc.sh install && sudo ./svc.sh start
```

Manual fallback (runner down): on the server, `cd ~/projects/lexserver.org && git pull --ff-only`
then `docker compose -p lexserver-web up -d --build`. Roll back by retagging
`lexserver-web-web:previous` as `:latest` and recreating the container.

### Gotchas

- Line endings are pinned to LF by `.gitattributes`. Do not re-add CRLF; prettier will fail CI.
- The Dockerfile sets `npm config set strict-ssl false` before `npm ci`. That disables TLS
  verification for npm inside the build; remove it if the server's network allows.
- Cloudflare may serve cached HTML for a short time after a deploy.
