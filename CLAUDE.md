## Commands

```bash
npm run dev        # Start Vite dev server (http://localhost:5173)
npm run build      # Production build -> dist/
npm run preview    # Serve the production build locally
npm run lint       # ESLint (TypeScript + React hooks + Prettier)
npm run format     # Prettier write
npm run test:e2e   # Build, then Playwright (mobile 375, tablet 768, desktop 1440)
npx tsc --noEmit   # Typecheck (CI runs this)
```

First time running the e2e tests on a machine: `npx playwright install`.

Docker (host port 8085 -> nginx 80):

```bash
docker compose up --build
```

## Architecture

A React app (Vite + TanStack Router file routes, pre-rendered to static HTML at build time) for Lexserver, the studio
of Alexies Iglesia and Charity Dultra (formerly branded "Builds Worlds Studio"; use Lexserver).
Routes live in `src/routes/`: `/`, `/work`, `/services`, `/about`, `/blog`, `/blog/$slug`, and
`/lupaatbahay` (a product case study). `src/routeTree.gen.ts` is generated by the router plugin.
Each route sets its own `<title>` and description in `head`; `__root.tsx` renders `<HeadContent />`
and must not render its own `<html>`/`<body>` (that wiped the theme class).

Do not add a route at `/products`: `public/products/` (images) is a directory, so nginx would serve
that instead. Products live in the `#products` section of the homepage.

Static pages in `public/` are served as-is, and win over SPA routes of the same path:
`public/indexwise/` (the Indexwise landing page) and `public/indexwise/privacy/` (its privacy
policy, which the Chrome Web Store listing links to — keep that URL stable). Do not add a React
route at `/indexwise`; it would be shadowed. The Indexwise pages are hand-written HTML styled by
`public/indexwise/indexwise.css`, which copies the site tokens from `src/styles.css` (keep in sync).

### Pre-rendering

`npm run build` runs three steps: the client build, an SSR build of
[src/entry-server.tsx](src/entry-server.tsx), and [scripts/prerender.mjs](scripts/prerender.mjs),
which renders every path in `STATIC_PATHS` (all pages plus each blog post) to `dist/<path>.html`,
writes `dist/404.html` and `dist/sitemap.xml`, and adds canonical, Open Graph and share-image tags.
`main.tsx` then hydrates that markup. A new route must be added to `STATIC_PATHS`, or nginx will
return 404 for it. Components must render the same thing on the server and in the browser: no
`window`/`document`/`localStorage` reads during render (use effects, the router's `useLocation`, or
`useSyncExternalStore` with a server snapshot, like `ThemeToggle`). Check for hydration errors in
the browser console after changes. Business details for Google are the JSON-LD block in
`index.html`; the share image is `public/og-image.png` (1200x630).

### Data flow

Page content lives in [src/lib/portfolio-data.ts](src/lib/portfolio-data.ts) as typed exported
constants (`PROFILE`, `SERVICE_GROUPS`, `PROCESS`, `PORTFOLIO`, `PRODUCTS`, `PRICING`, `TEAM`,
experience and awards). Section components read from it, so most copy changes are edits to that
one file. A few strings are hardcoded in components or route files (the hero, page intros,
`/lupaatbahay` page copy). Portfolio items with `hidden: true` are kept but not shown (no real
client name or image yet). `TESTIMONIALS` is not rendered; only add real quotes with permission.
Products with `status: "coming-soon"` are listed by name only. `status: "in-development"` products
get a full row with an "In development" badge. Blog posts are
markdown in `src/blog/posts/` (`YYYY-MM-DD-slug.md`), loaded by `src/lib/blog.ts`.

Adding a product: add an `OwnProduct` to `PRODUCTS`. An internal `url` starting with `/` renders as
"Learn more"; `storeLinks.website` and `storeLinks.chrome` render extra buttons.

### Components

Page sections are in [src/components/portfolio/](src/components/portfolio/).
[Page.tsx](src/components/portfolio/Page.tsx) holds the shared layout pieces every page is built
from (`PageShell`, `Container`, `Section`, `SectionHeader`, `PageHeader`, `Shot`, `ClosingCta`) and
the button/link class strings (`btnPrimary`, `btnSecondary`, `textLink`, `accentLink`, `label`).
Use these instead of new one-off styles. `Nav.tsx` is the sticky header, `WorkList.tsx` renders the
featured case study and client work rows, and `OfficeDemo.tsx` embeds the AI Office preview in an
iframe.

### Styling

Calm, editorial style (design guide: https://claude.ai/artifact/BiGFyhoePLWP5j97dCTh35). Tailwind
CSS v4, light and dark themes. The theme is applied before paint by `public/theme-init.js` (an
external file because the CSP blocks inline scripts): saved choice first, else the system setting.
Tokens in [src/styles.css](src/styles.css): `bg-bg`, `bg-surface`, `text-fg`, `text-muted`,
`border-line`, `bg-accent` / `text-accent` (ink blue `#3346b8`, `#8c9cff` in dark), `bg-accent-soft`.
Font: Geist (sans) and Geist Mono (small labels only). Rules: sentence case, no all-caps text, one
primary button per screen, accent only on the main button and links, whitespace and thin dividers
instead of bordered cards, no stock photos or decorative graphics. Long-form text uses `.prose-site`.

### Images

Product and case-study images are webp in `public/products/`. Keep them under ~150 KB each. Use
real screenshots only. Nginx CSP `img-src` only allows `'self'` and `data:`, so externally hosted
images are blocked until the CSP is updated.

## Build and deployment

Vite builds a static bundle into `dist/`. The Docker image is two-stage: Node 22 builds, then
nginx:alpine serves `dist/` with `try_files $uri $uri.html $uri/ =404` (so `/work` serves
`work.html`, a trailing slash redirects to the bare URL, unknown paths get `404.html`) and the
security headers and CSP
from [nginx.conf](nginx.conf). The CSP must list every external origin the site uses: currently
Google Fonts and `frame-src https://aiteampreview.lexserver.org` for the AI Office
demo (it is repeated in each `location` block).

### CI/CD

[.github/workflows/ci.yml](.github/workflows/ci.yml):

- `verify` (GitHub-hosted, every push and pull request): `npm ci --legacy-peer-deps`, lint,
  `tsc --noEmit`, build.
- `deploy` (self-hosted runner on lexserver, label `lexserver`, push to `main` only, after
  `verify`): tags the current image `lexserver-web-web:previous`, runs
  `docker compose -p lexserver-web up -d --build`, health-checks `/`, `/lupaatbahay`,
  `/indexwise/` and `/api/health` on port 8085, and rolls back to `:previous` if any fail.

### Contact form

The `#contact` form posts JSON to `/api/contact`. nginx proxies `/api/` to the `api` service in
`docker-compose.yml` ([server/contact.mjs](server/contact.mjs), Node + nodemailer, not exposed on
the host). It saves every message to `messages.jsonl` in the `contact-data` volume, then emails it
to `CONTACT_TO` with the sender as Reply-To. SMTP settings come from a `.env` file next to
`docker-compose.yml` on the server (see `.env.example`; never commit it). Without SMTP settings, or
if sending fails, the API answers 503 and the page offers a prefilled mailto link instead. Spam
guards: a hidden honeypot field, 5 messages per IP per hour in the API, and an nginx rate limit
keyed on `CF-Connecting-IP`. Read saved messages with
`docker exec lexserver-web-api-1 cat /data/messages.jsonl`.

The compose project name `lexserver-web` must stay: it produces the container
`lexserver-web-web-1`, the image `lexserver-web-web`, and the network `lexserver-web_default`.

One-time runner setup on the server (runners are per repo; the existing lupaatbahay one cannot
serve this repo). Get a registration token from GitHub (repo -> Settings -> Actions -> Runners ->
New self-hosted runner), then:

```bash
ssh ialexies@192.168.0.253
mkdir -p ~/actions-runner-lexserver-org && cd ~/actions-runner-lexserver-org
# download and extract the runner release (same version as ~/actions-runner-homescout)
./config.sh --url https://github.com/ialexies/lexserver.org --token <TOKEN> \
  --name lexserver-org --labels self-hosted,lexserver --unattended --work _work
sudo ./svc.sh install && sudo ./svc.sh start
```

Manual fallback (runner down): on the server, `cd ~/projects/lexserver.org && git pull --ff-only`
then `docker compose -p lexserver-web up -d --build`. Roll back by retagging
`lexserver-web-web:previous` as `:latest` and recreating the container.

### Gotchas

- Line endings are pinned to LF by `.gitattributes`. Do not re-add CRLF; prettier will fail CI.
- The Dockerfile sets `npm config set strict-ssl false` before `npm ci`. That disables TLS
  verification for npm inside the build; remove it if the server's network allows.
- Cloudflare may serve cached HTML for a short time after a deploy.
